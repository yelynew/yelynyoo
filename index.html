D Debugging the event-generation QA tool

I built a local Python/Flask app, with AI assistance, that lets testers fire security events from a web form and inspect the resulting service logs. One output did not match its input, and the defect turned out to be in AI-generated code:

  1. Reproduce
    Held all inputs constant and varied one at a time until the mismatch was deterministic.
  2. Trace
    Followed the request through service logs and compared fields at each hop.
  3. Root cause
    An AI-generated feature silently discarded the entered port value before the event was built.
  4. Fix
    Corrected the parameter handling in the generation logic.
  5. Verify
    Re-ran the controlled inputs and confirmed expected output end to end.

Takeaway Generated code gets the same controlled tests and log checks as anything else before it ships.

Doorstep — event wayfinding for USC

Nov 2026 · team project · 38 of ~170 commits are mine · source ↗

Gets event attendees to the right door of a building, then to the room. A QR link like /?to=JMC&room=258 routes from wherever you are on campus, around whatever staff have closed right now, and hands off to indoor directions at the door. Driving mode picks a parking structure by gate hours, permits and game days, then switches to walking.

Who reports a closureEffect on routes
AnyoneUnverified. Warning on routes passing within 30 m; no reroute
Staff (admin token)Approved. Edges blocked, routes bend around it and show “+N min”
Every closureHas start/end times and lapses on its own (default 4 h)
 
# cloudflare/router.mjs — what a closure costs (excerpt)
found = this.search(targets, blocked, stepFree, virtual, vout)   // with closures
if (blocked.size)
  base = this.search(targets, new Map(), stepFree, virtual, vout) // without
avoided = baseClosures.map(closure =>
  ({closure, extra_min: round1(Math.max(0, found.cost - base.cost) / 60)}))
Our own router
Google can't route around our closures, and its terms forbid storing routes or drawing them on other maps. Paths come from OpenStreetMap (ODbL); the search is multi-target Dijkstra over travel seconds to every door of the venue.
Immutable graph, virtual edges
The compiled graph is shared across requests and never mutated. Each request snaps its start to the nearest edge within 150 m and splits it with request-local virtual edges.
Python ↔ JS parity
The Worker is a port of the original Python engine. floorDiv reproduces CPython's float // so spatial-grid cells match exactly, and a parity script compares both engines' routes.
Step-free routing
Prefers doors surveyed as level, ramp or elevator and prunes stair edges. When nothing is left, the error says why: “stairs on every way in” vs. “every way in is closed”.
Quota-safe driving
The provider allows 40/min (sliding) and 2,000/day; our fixed-window counters cap at 20/min and 1,000/day, so a burst across a window boundary still stays under. A used-up day falls back to a maps-app hand-off, not an error.
AI suggests, people decide
Ask Doorstep answers only from facts the app sends, with citations; uncited answers are dropped and the question goes to organizers. Photo triage suggests a category, but only staff can close a path.

CampusLoop — carpooling with a local RAG assistant

2026 · ACM@USC Hackathon · team project · source ↗

A carpooling app for students: ride offers and requests, recurring trips, per-date waitlists, and fares computed from Google Routes quotes. It ships with a fully local RAG assistant that answers policy and ride questions with citations, running on CPU inside Docker Compose. 

# app/rag.py — reciprocal rank fusion (excerpt)
lexical = bm25(question, docs)
ranks   = sorted(range(len(docs)), key=lambda i: lexical[i], reverse=True)
fusion  = {i: 1 / (60 + r) for r, i in enumerate(ranks) if lexical[i] > 0}

for r, j in enumerate(semantic_order):        # cosine order over top-8
    i = candidates[j]
    fusion[i] = fusion.get(i, 0) + 1 / (60 + r)

best = sorted(fusion, key=fusion.get, reverse=True)[:3]   # → S1, S2, S3
Lexical first
Policy Q&A is keyword-heavy, and a second model load is expensive on CPU. Dense re-ranking is opt-in and only touches the 8 BM25 candidates, never the full corpus.
Graceful degradation
Embedding failure → BM25-only with a warning. Generation failure → return the retrieved sources without an answer (retrieval_only) rather than an error.
Bounded concurrency
A BoundedSemaphore(2) guards inference; a third simultaneous request gets HTTP 429 instead of queueing behind a slow CPU model.
Content-addressed cache
Vectors are keyed by (sha256(text), model) in SQLite and embedded in batches of 16, so unchanged chunks are never re-embedded and switching models can't mix spaces.
Fare model
E(n) = B · (1 + 0.65 (n − 1)), rider price E(n) / n, where B is the base from a traffic-aware Routes quote. Decimal arithmetic, half-up rounding to cents; no quote, no booking.
Container hardening
Read-only root filesystem, cap_drop: [ALL], no-new-privileges, port bound to 127.0.0.1. Model weights are pulled and warmed by a separate init container.

My part

  • Backend
    SQLite-backed ride data and JSON REST endpoints.
  • RAG assistant
    Locally hosted Ollama / BM25 assistant with source-cited answers.
  • Features
    Recurring rides and a demo mode, with tests.

Verification 132 tests passing (v2.5.0), including concurrent-approval overbooking and idempotent retries.

Pretraining-data detection with Min-K% Prob

2026 · USC Machine Learning · in progress

Given a black-box language model and a passage, was the passage in its pretraining data? Min-K% Prob answers without the training corpus: text the model has seen rarely contains tokens it finds very surprising, so the mean log-likelihood of its least likely tokens is a membership signal. I reproduced the method on 542 WikiMIA examples and benchmarked it against three baselines across two Pythia models.

Min-K%(x) = 1⁄E Σxi ∈ Min-K%(x) log p(xi | x1, …, xi−1) E = number of tokens in the lowest-k% set. Flag as “seen” when the score exceeds a threshold.
  1. Score
    Compute per-token log-probabilities under the target model.
  2. Select
    Keep the k% lowest-probability tokens.
  3. Aggregate
    Average their log-probabilities into one score per passage.
  4. Evaluate
    Sweep the threshold on WikiMIA member / non-member splits; report AUC and TPR.
  5. Compare
    Benchmark against perplexity, zlib and reference-model baselines on two Pythia models.
